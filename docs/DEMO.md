## Runbook — πώς σηκώνουμε το demo (Κυριακή)

```bash
# Laptop Δημήτρη
./scripts/dev_backend.sh                         # forecast → Mock ERP :8080 → App API :8000
cd apps/web && npm run build && npm start        # dashboard http://localhost:3000 (production build, γρήγορο)
apps/voice/deploy/tunnel.sh                      # laptop:8100 → voice agent στο VPS, VPS:18000 → App API :8000

# Έλεγχοι πριν ανέβουμε (≈30″, δεν πειράζουν το state του demo)
python3 scripts/check_voice_vs_api.py            # voice agent πάνω στο πραγματικό API: ΟΛΑ ΟΚ
curl -s localhost:8100/voice/health              # ο voice agent απαντά μέσω tunnel
```

Πριν ξεκινήσουμε: **Επισκόπηση → «Επαναφορά demo»** (όλες οι προτάσεις «Προς έγκριση», καμία κλήση).

Σενάριο click-by-click:
1. **Επισκόπηση** → «Πελάτες σε κίνδυνο», εξαντλήσεις ανά μέρα.
2. **At Risk** → φίλτρο πωλητή «Στέλιος Παπαγεωργίου», ορίζοντας 3 μέρες.
3. **Πελάτες → Mini Market Οικονομικό (1004)** → γράφημα Ice tea, chip «Απόθεμα από προσφορά», εξήγηση.
4. **Κλήσεις** → πωλητής 105 → «Κάλεσε» → το κινητό χτυπά: «Γιατί τόσα;» → «κάν' τα …» → «ναι, επιβεβαιώνω».
   Η κάρτα της κλήσης δείχνει live βήματα, transcript και `DRAFT-…`.
5. **Παραγγελίες → «Στο ERP»** → η ίδια παραγγελία με το draft id. (Εναλλακτικά: έγκριση από το dashboard.)
6. **Αξιολόγηση** → MAE 3,6 vs baseline 11,3 · 1.975 / 1.975 ζεύγη.

Αν δεν πιάνει η κλήση: ηχογράφηση (fallback) + έγκριση από τη σελίδα Παραγγελίες — η ροή ERP είναι ίδια.
