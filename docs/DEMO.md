## Runbook — πώς σηκώνουμε το demo (Κυριακή)

```bash
# Laptop Δημήτρη
./scripts/dev_backend.sh                         # Mock ERP :8080 → VORA agent (διαβάζει από το ERP) → App API :8000
cd apps/web && npm run build && npm start        # dashboard http://localhost:3000 (production build, γρήγορο)
VPS_KEY=~/.ssh/id_ed25519 apps/voice/deploy/tunnel.sh   # laptop:8100 → voice agent στο VPS, VPS:18000 → App API :8000
                                                 # (VPS_KEY: στο laptop του Δημήτρη το κλειδί είναι το id_ed25519)

# Έλεγχοι πριν ανέβουμε (≈30″, δεν πειράζουν το state του demo)
python3 scripts/check_voice_vs_api.py            # voice agent πάνω στο πραγματικό API: ΟΛΑ ΟΚ
curl -s localhost:8100/voice/health              # ο voice agent απαντά μέσω tunnel
```

Πριν ξεκινήσουμε: **Επισκόπηση → «Επαναφορά demo»** (όλες οι προτάσεις «Προς έγκριση», καμία κλήση).

Σενάριο click-by-click:
0. **Agent** → «Τρέξε τον agent τώρα»: σε ~4″ φαίνονται live τα βήματα — 25.184 τιμολόγια από το ERP → καθαρισμός →
   1.975 προβλέψεις → 124 Suggested Orders (35 κρίσιμες) → 124/124 περνούν τους κανόνες του ERP → αυτοέλεγχος 2,9 μέρες.
   «Αυτός είναι ο agent: μόνος του, κάθε πρωί στις 6· ο πωλητής μόνο εγκρίνει.»
1. **Επισκόπηση** → «Με ποιους να ξεκινήσεις» (κρίσιμοι κατά αξία) και «Πιθανή απώλεια».
2. **At Risk** → φίλτρο πωλητή «Στέλιος Παπαγεωργίου», ορίζοντας 7 μέρες.
3. **Πελάτες → Mini Market Οικονομικό (1004)** → γράφημα Ice tea, chip «Απόθεμα από προσφορά», εξήγηση.
4. **Κλήσεις** → πωλητής 105 → «📞 Live κλήση στο κινητό» (πράσινο «έτοιμος να καλέσει» = tunnel ΟΚ) → η VORA μιλά για **ένα προϊόν** του πιο επείγοντα πελάτη → το κινητό χτυπά: «Γιατί τόσα;» → «κάν' τα …» → «ναι, επιβεβαιώνω».
   Η κάρτα της κλήσης δείχνει live βήματα, transcript και `DRAFT-…`.
   **Plan B, χωρίς τηλέφωνο:** «▶ Προσομοίωση κλήσης» στην ίδια κάρτα → η VORA «καλεί» τον πωλητή για τον
   πιο επείγοντα at-risk πελάτη του, με φωνή από τον browser (~1½ λεπτό): γιατί κινδυνεύει (από το evidence) → πρόταση →
   αλλαγή ποσότητας → περίληψη → «ναι, επιβεβαιώνω» → πραγματικό draft στο ERP. Κάθε πάτημα → ο επόμενος πελάτης.
5. **Παραγγελίες → «Στο ERP»** → η ίδια παραγγελία με το draft id. (Εναλλακτικά: έγκριση από το dashboard.)
6. **Αξιολόγηση** → MAE 2,9 μέρες vs baseline 13,2 · 92% εντός ±7 · 1.975 / 1.975 ζεύγη.

Αν δεν πιάνει η κλήση: ηχογράφηση (fallback) + έγκριση από τη σελίδα Παραγγελίες — η ροή ERP είναι ίδια.
