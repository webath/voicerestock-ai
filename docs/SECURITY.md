# VORA — Ασφάλεια (brief για την επιτροπή)

> Μία φράση: **το AI προτείνει, ο άνθρωπος αποφασίζει, και ο server επιβάλλει τους κανόνες — όχι το prompt.**
> Κάθε μέτρο παρακάτω είναι υλοποιημένο και καλύπτεται από tests (`apps/api/tests/test_security.py` κ.ά.).

## 1. Κανένα AI δεν παραγγέλνει μόνο του
- Στο ERP γράφεται **μόνο DRAFT**, ποτέ τελική παραγγελία· μόνο το App API γράφει στο ERP.
- Draft μόνο μετά από **ρητή έγκριση**: στο dashboard (κουμπί) ή στη φωνή — η VORA διαβάζει **ακριβή περίληψη** και
  περιμένει «ναι, επιβεβαιώνω».
- **Exactly-once**: confirmation token δεμένο σε (πρόταση, έκδοση) + idempotency key + lock γύρω από το POST στο ERP.
  Δύο ταυτόχρονες επιβεβαιώσεις ή κομμένη γραμμή → **ένα** draft (`scripts/check_voice_vs_api.py`: «ΟΛΑ ΟΚ»).
- Αλλαγή ποσότητας → νέα έκδοση, οι παλιές επιβεβαιώσεις ακυρώνονται (409 `version_conflict`).

## 2. Το LLM δεν βγάζει ποτέ αριθμούς
- Ποσότητες, ημερομηνίες, confidence βγαίνουν από **ντετερμινιστικό** μοντέλο (backtest MAE 2,9 μέρες).
  Το LLM μόνο **εξηγεί** από το `evidence`.
- Το LLM δίνει μόνο ids (`suggestion_id`, `mtrl`, `qty`)· ο server ελέγχει ότι η πρόταση **ανήκει στον πωλητή της κλήσης**,
  ότι η ποσότητα είναι ακέραιος μέσα σε `QTY_MIN..QTY_MAX` (StrictInt — όχι «5» ως κείμενο), και πάνω από 2× ξαναρωτά.
- Ο AI βοηθός του dashboard είναι **μόνο ανάγνωσης**. Ρόλοι μηνυμάτων μόνο `user/assistant` — δεν γίνεται να «σπρώξει»
  κανείς δικό του `system` prompt. Prompt injection δεν μπορεί να γράψει τίποτα: τα εργαλεία εγγραφής δεν υπάρχουν εκεί.

## 3. Τίποτα ανοιχτό στο internet
- App API, dashboard (`scripts/start.sh`), mock ERP (`scripts/mock_erp_local.py`) και voice agent ακούνε **μόνο σε 127.0.0.1** — ούτε το ίδιο Wi-Fi τα βλέπει. Laptop ↔ VPS μόνο μέσω **SSH tunnel με κλειδί**, localhost και στα δύο άκρα.

## 4. Άμυνες web του App API (`apps/api/app/security.py`)
| Επίθεση | Άμυνα |
|---|---|
| Ξένη σελίδα στέλνει αίτημα στο localhost (CSRF) | Κάθε εγγραφή θέλει header `X-Actor` → ο browser κάνει preflight που ξένη σελίδα δεν περνά (403) |
| Ξένη προέλευση | Origin/CORS **μόνο** το dashboard (`WEB_ORIGINS`) → 403 |
| DNS rebinding | Host allowlist `localhost/127.0.0.1` (`API_ALLOWED_HOSTS`) → 400 |
| Κατάχρηση κόστους / spam | Όρια ρυθμού: SMS 5/λεπτό, LLM 20/λεπτό, ERP drafts 30/λεπτό, reset 3/λεπτό → 429 |
| Τεράστια αιτήματα | Όριο σώματος 64 KB → 413· όρια μήκους σε chat (4.000 χαρ., 40 μηνύματα) και call events |
| Clickjacking, sniffing, cache | `frame-ancestors 'none'`, `X-Frame-Options: DENY`, `nosniff`, `no-store`, `no-referrer` (API + dashboard), `Permissions-Policy` χωρίς κάμερα/γεωθέση |

## 5. Φωνή (κλήσεις)
- Η VORA **λέει από την αρχή ότι είναι AI**. Αν απαντήσει τηλεφωνητής ή άλλος άνθρωπος: **κανένα στοιχείο πελάτη, καμία παραγγελία**.
- Κλήσεις μόνο σε **allowlist αριθμών**, όχι σε **ώρες ησυχίας**, trigger με `X-Voice-Token`.
- Ποσότητες/ημερομηνίες λέγονται **με λέξεις** (το φωνητικό μοντέλο μπερδεύει ψηφία) — λιγότερα λάθη ακοής.
- «Έγινε» λέγεται μόνο όταν το ERP επιστρέψει `erp_draft_id`.

## 6. SMS & προσωπικά δεδομένα
- SMS μόνο σε **πελάτη-στόχο** εγκεκριμένης πρότασης, μόνο με **δικό σου κουμπί**· ένα πάτημα = ένα SMS (idempotency), ως 3 τμήματα.
- Τηλέφωνα **μασκαρισμένα** παντού (`+30694•••0522`), **ποτέ** στο LLM (παίρνει μόνο όνομα πελάτη/είδη).
- Τα δεδομένα της Revival δεν έχουν κινητά. **Demo** (default): όλα πάνε σε ένα εγκεκριμένο κινητό (`SMS_DEMO_TO`).
  **Πραγματικά**: ο χρήστης ανεβάζει επαφές (σελίδα Πελάτες) και το ενεργοποιεί με ρητή επιβεβαίωση· πελάτης χωρίς κινητό
  **δεν** παίρνει SMS (ποτέ σιωπηλή επιστροφή στο demo κινητό). Οι επαφές μένουν σε τοπικό αρχείο, gitignored, `chmod 600`.

## 7. Ο agent δεν δημοσιεύει σκουπίδια
- Κάθε πρόταση περνά κανόνες ERP (γνωστός πελάτης/είδος, ποσότητα > 0, παράδοση σε εργάσιμη πριν την εξάντληση).
- **Αυτοέλεγχος**: αν το backtest MAE ξεπεράσει το όριο, **δεν δημοσιεύει** — μένουν οι προηγούμενες. Δημοσίευση atomic.

## 8. Secrets, ιχνηλασιμότητα, εξαρτήσεις
- Κλειδιά μόνο στο `.env` (gitignored, `chmod 600`). **Σάρωση όλου του git ιστορικού: 0 κλειδιά** (Anthropic, Apifon, SSH, AWS, GitHub).
- **Audit log** για κάθε εγγραφή: ποιος (`dashboard`, `voice:<κλήση>`, `agent`), τι, πότε, αποτέλεσμα, correlation id.
  Transcript κάθε κλήσης και ιστορικό εκτελέσεων agent.
- `pip-audit`: **0 γνωστές ευπάθειες** · `npm audit`: **0** · κλειδωμένες εκδόσεις (`uv.lock`, `package-lock.json`).

## Τι θα κάναμε σε παραγωγή (τίμια όρια του demo)
- **Login/SSO (OIDC) με ρόλους** — κάθε πωλητής βλέπει μόνο τους πελάτες του. Σήμερα: ένας χρήστης, τοπικά.
- Κρυπτογράφηση της βάσης (SQLite → Postgres με encryption at rest), όρια ρυθμού σε Redis αντί για μνήμη.
- Μη-root χρήστης στο VPS, secrets manager αντί για `.env`, rotation κλειδιών μετά το hackathon.
- Mutual TLS ή υπογεγραμμένα αιτήματα voice → API (σήμερα: SSH tunnel + localhost).
