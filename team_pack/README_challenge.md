# Challenge #5 — The Intelligent Restocking Agent: Bridging ERPs with AI

**Revival Consulting · ΕΚΠΑ Student Open Innovation Hackathon · 6–8 Νοεμβρίου 2026**

## 1. Το σενάριο

Είστε η ομάδα data της **DEMO ΔΙΑΝΟΜΕΣ Α.Ε.**, χονδρεμπόρου τροφίμων, ποτών και αναλωσίμων για HoReCa και mini markets. **Σήμερα είναι 1/11/2026.** Το ERP (σε μορφή SoftOne) καταγράφει μόνο ό,τι **πουλήθηκε** στον πελάτη. Δεν γνωρίζουμε πόσο απόθεμα έχει ο ίδιος ο πελάτης ούτε πόσο καταναλώνει.

Ζητούνται:
1. **Σωστή ανάγνωση** των παραστατικών (header/lines).
2. **Burn rate** ανά πελάτη × είδος.
3. **Πρόβλεψη** της ημερομηνίας εξάντλησης του αποθέματος κάθε πελάτη για κάθε είδος και δημιουργία **«Suggested Order» JSON** πριν από αυτήν.
4. **Dashboard** με τους πελάτες «At Risk».

Όλα τα δεδομένα είναι **100% συνθετικά**. Δεν υπάρχουν πραγματικές εταιρείες, ΑΦΜ, τηλέφωνα ή email. Το ιστορικό καλύπτει **2024-01-02 έως 2026-10-31** (cutoff). Η αξιολόγηση γίνεται για τις **90 ημέρες μετά το cutoff** (2026-11-01 έως 2027-01-29).

## 2. Αρχεία (`data/`)

Όλα είναι UTF-8, χωρισμένα με κόμμα, με ημερομηνίες ISO (`YYYY-MM-DD`) και δεκαδικά με τελεία.

Τα CSV έχουν UTF-8 BOM, ώστε να ανοίγουν στο Excel με σωστά ελληνικά. Το pandas το χειρίζεται αυτόματα. Με το `csv` module της Python ανοίξτε τα με `encoding='utf-8-sig'`, αλλιώς η πρώτη στήλη θα λέγεται `\ufeffTRDR`. Στο Node, με `csv-parse` βάλτε `bom: true`. Το `saldoc.json` δεν έχει BOM.

| Αρχείο | Περιεχόμενο |
|---|---|
| `TRDR.csv` | Πελάτες |
| `MTRL.csv` | Είδη και υπηρεσίες |
| `PRSN.csv` | Πωλητές |
| `SALDOC.csv` | Κεφαλίδες παραστατικών πώλησης (headers) |
| `MTRLINES.csv` | Γραμμές παραστατικών (lines) |
| `saldoc.json` | Οι ίδιες κεφαλίδες με φωλιασμένο πίνακα `LINES` (compact JSON) |

| `greek_holidays.csv` | Αργίες 2024–2027 |
| `prediction_targets.csv` | Τα ζεύγη (πελάτης, είδος) που πρέπει να προβλέψετε |

### Data dictionary

**TRDR.csv**: `TRDR` (id πελάτη), `CODE` (π.χ. `30.00.0001`), `NAME`, `TRDCATEGORY` (Mini Market / Καφέ-Μπαρ / Εστιατόριο / Ξενοδοχείο), `AREA` (Αθήνα / Πειραιάς / Θεσσαλονίκη / Κυκλάδες / Κρήτη), `CITY`, `SALESMAN` (→ `PRSN`), `INSDATE` (ημερομηνία πρώτης καταχώρισης), `ISACTIVE` (1/0).

**MTRL.csv**: `MTRL` (id), `CODE`, `NAME` (περιέχει συσκευασία), `MTRCATEGORY`, `MTRTYPE` (**0 = είδος, 1 = υπηρεσία**), `MTRUNIT1` (`ΚΙΒ` = κιβώτιο, `ΤΕΜ` = τεμάχιο), `PRICER` (τρέχουσα τιμή καταλόγου χονδρικής 2026).

**PRSN.csv**: `PRSN` (id), `NAME`.

**SALDOC.csv** (ένα record ανά παραστατικό):

| Πεδίο | Περιγραφή |
|---|---|
| `FINDOC` | Μοναδικό id παραστατικού (κλειδί σύνδεσης με τις γραμμές) |
| `COMPANY` | Πάντα 1001 |
| `SOSOURCE` | Πάντα 1351 (πωλήσεις) |
| `SERIES` | **7021** = Τιμολόγιο Πώλησης, **7071** = Πιστωτικό Τιμολόγιο |
| `FINCODE` | Αριθμός παραστατικού (`ΤΠΑ0001234` / `ΠΙΣ0000123`) |
| `TRNDATE` | Ημερομηνία παραστατικού. **Είναι η μοναδική ημερομηνία** και ταυτίζεται με την ημερομηνία παράδοσης |
| `TRDR` | Πελάτης |
| `SALESMAN` | Πωλητής |
| `ISCANCEL` | 1 = ακυρωμένο παραστατικό |
| `NETAMNT`, `VATAMNT`, `SUMAMNT` | Καθαρή αξία, ΦΠΑ, σύνολο (σε EUR). Είναι πάντα θετικά, ακόμη και στα πιστωτικά |
| `COMMENTS` | Ελεύθερο κείμενο |

**MTRLINES.csv** (πολλές γραμμές ανά παραστατικό):

| Πεδίο | Περιγραφή |
|---|---|
| `FINDOC` | Παραστατικό (→ `SALDOC.FINDOC`) |
| `MTRLINES` | Αύξων αριθμός γραμμής (1..n) μέσα στο παραστατικό |
| `MTRL` | Είδος |
| `QTY1` | Ποσότητα στη βασική μονάδα (`MTRUNIT1`). **Πάντα θετική** |
| `PRICE` | Τιμή μονάδας |
| `DISC1PRC` | Έκπτωση % (0–100) |
| `LINEVAL` | Καθαρή αξία γραμμής μετά την έκπτωση = `QTY1 × PRICE × (1 − DISC1PRC/100)` |
| `VAT` | Συντελεστής ΦΠΑ της γραμμής (13 ή 24, δηλαδή ποσοστό) |

Ο ΦΠΑ είναι 13% για τρόφιμα, νερά, αναψυκτικά, καφέ, παγωτά και εποχικά, και 24% για τα υπόλοιπα (μπύρες, χαρτικά, απορρυπαντικά, μεταφορικά). `NETAMNT` = άθροισμα `LINEVAL` του παραστατικού και `VATAMNT` = άθροισμα `LINEVAL × VAT/100` (ανά γραμμή, στρογγυλοποιημένο στο λεπτό).

**PROMO.csv**: `PROMO`, `NAME`, `MTRL` **ή** `MTRCATEGORY` (συμπληρωμένο το ένα από τα δύο), `FROMDATE`, `TODATE` (συμπεριλαμβανομένων), `DISC_PRC` (έκπτωση %).

**greek_holidays.csv**: `DATE`, `NAME`, `TYPE` (`PUBLIC_HOLIDAY` = επίσημη αργία, `EASTER_SUNDAY` = Κυριακή του Πάσχα).

**prediction_targets.csv**: `TRDR`, `MTRL`. Περιλαμβάνει κάθε ζεύγος με τουλάχιστον 3 αγορές από μη ακυρωμένα τιμολόγια και τελευταία αγορά τις 120 ημέρες πριν το cutoff, καθώς και τα ενεργά ζεύγη των νέων πελατών με τουλάχιστον 1 αγορά.

**submission_template.csv**: `TRDR`, `MTRL`, `PREDICTED_DEPLETION_DATE`, `SUGGESTED_QTY` (προσυμπληρωμένο με τα ζεύγη-στόχους).

## 3. Πώς ενώνονται header και lines

Οι γραμμές **δεν έχουν ημερομηνία ούτε πελάτη**. Πρέπει να τα πάρετε από τον header:

```
MTRLINES.FINDOC = SALDOC.FINDOC   →   TRNDATE, TRDR, SERIES, ISCANCEL ...
```

Στο `saldoc.json` οι γραμμές είναι ήδη φωλιασμένες στο πεδίο `LINES` κάθε header.

## 4. Σημειώσεις ρεαλισμού (διαβάστε τες προσεκτικά)

- **Ακυρωμένα παραστατικά**: περίπου 1,5% των τιμολογίων έχουν `ISCANCEL = 1`. Οι γραμμές τους **υπάρχουν** στο `MTRLINES`. Δεν είναι πραγματική παράδοση και δεν πρέπει να επηρεάζουν το απόθεμα του πελάτη.
- **Πιστωτικά (επιστροφές)**: περίπου 2% των παραστατικών είναι πιστωτικά `SERIES = 7071`. Όπως στο SoftOne, οι γραμμές τους έχουν **θετική** `QTY1`. Ο τύπος του header (`SERIES`) δείχνει ότι πρόκειται για επιστροφή, η οποία **μειώνει** το απόθεμα του πελάτη.
- **Δωρεάν ποσότητες (free goods)**: ορισμένες φορές το ίδιο `MTRL` εμφανίζεται δύο φορές στο ίδιο τιμολόγιο. Η μία γραμμή είναι κανονική και η δεύτερη έχει `PRICE = 0` και `DISC1PRC = 100` (π.χ. «1 κιβώτιο δώρο ανά 10»). **Και οι δύο ποσότητες παραδόθηκαν πραγματικά.**
- **Υπηρεσία «Μεταφορικά»** (`MTRTYPE = 1`): εμφανίζεται σε περίπου 10% των τιμολογίων. Δεν είναι εμπόρευμα και **πρέπει να αποκλειστεί** από τους υπολογισμούς.
- **Εποχικά είδη** (κατηγορία «Εποχικά»): πωλούνται μόνο σε συγκεκριμένα χρονικά παράθυρα του έτους.
- **Προσφορές**: το `PROMO.csv` περιλαμβάνει προσφορές του παρελθόντος και **2 προσφορές μέσα στο ορίζοντα πρόβλεψης (Νοέμβριος–Δεκέμβριος 2026)**. Οι γραμμές που πωλήθηκαν με προσφορά έχουν `DISC1PRC > 0`. Οι τιμές καταλόγου αυξάνονται κάθε Ιανουάριο, οπότε το `PRICE` αλλάζει με το έτος.
- **Αργίες και Κυριακές**: δεν γίνονται παραδόσεις (άρα ούτε παραστατικά) τις Κυριακές και τις επίσημες αργίες (`greek_holidays.csv`). Οι πελάτες έχουν σταθερές ημέρες δρομολογίου, και τα παραστατικά ακολουθούν αυτές τις ημέρες.
- Οι ποσότητες είναι ακέραιες (κιβώτια ή τεμάχια). Η παράδοση γίνεται την ίδια ημέρα με το παραστατικό.
- Οι αγορές δεν είναι ευθεία γραμμή: οι πελάτες διαφέρουν ως προς τον τύπο, την περιοχή και το μέγεθος, και η κατανάλωση μπορεί να αλλάζει στο χρόνο. Ορισμένοι πελάτες έχουν μικρό ιστορικό (cold start). Για ορισμένα ζεύγη μπορεί να μην προκύπτει εξάντληση μέσα στον ορίζοντα των 90 ημερών.

## 7. Πώς βαθμολογείται η ακρίβεια

Για κάθε ζεύγος του `prediction_targets.csv` συγκρίνεται η πρόβλεψή σας με την πραγματική ημερομηνία εξάντλησης. Αυτή είναι η πρώτη ημέρα μετά το cutoff (2026-10-31) που το απόθεμα του πελάτη θα έφτανε στο 0 αν δεν γίνονταν άλλες παραδόσεις. Ορίζουμε το `horizon_end` = **2027-01-29** (cutoff + 90 ημέρες).

Σφάλμα ανά ζεύγος, σε ημέρες:

| Περίπτωση | Σφάλμα |
|---|---|
| Λείπει το ζεύγος ή η ημερομηνία δεν διαβάζεται | **60** |
| Αληθινή = ημερομηνία, πρόβλεψη = ημερομηνία | `abs(πρόβλεψη − αληθινή)` |
| Αληθινή = καμία εξάντληση, πρόβλεψη κενή ή `≥ horizon_end` | 0 |
| Αληθινή = καμία εξάντληση, πρόβλεψη πριν το `horizon_end` | `horizon_end − πρόβλεψη` |
| Αληθινή = ημερομηνία, πρόβλεψη κενή (ή `≥ horizon_end`) | `horizon_end − αληθινή` |

Αναφέρονται:
- **n scored**: το πλήθος των ζευγών που βαθμολογούνται.
- **MAE** σε ημέρες, δηλαδή ο μέσος όρος των σφαλμάτων (ο βασικός δείκτης κατάταξης).
- **% εντός ±3 ημερών** και **% εντός ±7 ημερών**.
- **Precision και recall για «At Risk»**: είναι At Risk κάθε ζεύγος με εξάντληση το πολύ 14 ημέρες μετά το cutoff (δηλαδή έως 2026-11-14). Ένα ζεύγος που προβλέπετε με ημερομηνία ≤ 2026-11-14 θεωρείται ότι το έχετε δηλώσει At Risk. Precision = σωστά At Risk / όσα δηλώσατε. Recall = σωστά At Risk / όσα ήταν πραγματικά At Risk.

Ορισμένα ζεύγη-στόχοι **δεν** μετράνε στο MAE και αναφέρονται ξεχωριστά (count). Δεν σας λέμε ποια είναι· γράψτε πρόβλεψη για **όλα** τα ζεύγη του template.

Σημεία αναφοράς: η πρόβλεψη «όλοι = cutoff + 30 ημέρες» έχει MAE περίπου 18,3 ημέρες. Ένα απλό baseline με μέσο ρυθμό κατανάλωσης των τελευταίων 180 ημερών έχει MAE περίπου 16,1 ημέρες. Στόχος είναι να πέσετε σημαντικά κάτω από αυτό.
